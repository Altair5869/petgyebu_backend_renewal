# PRD: Petgyebu 수동 지출 가계부 MVP

- 기준일: 2026-09-25
- 상태: 새 MVP 기획 기준. `sources/`의 기존 문서는 과거 설계 기록이다.
- 대상: React Native 모바일 앱과 Spring Boot 백엔드

## 1. 제품 목표

사용자가 지출을 직접 기록하고 월 예산 대비 소비를 확인하며, 선택한 반려동물의 상태와 간단한 성장 변화를 통해 기록을 이어가게 한다.

## 2. 대상과 검증할 가설

처음 월 예산을 관리하는 20~30대 사용자를 대상으로 한다. 짧은 입력과 직관적인 반려동물 표현이 첫 지출 기록과 다음 주 재방문에 도움이 되는지 검증한다. 금융 계좌의 포괄적인 내역을 제공한다는 약속은 하지 않는다. 사용자가 입력한 지출만 합산한다.

## 3. MVP 범위

| 영역 | 제공 내용 |
|---|---|
| 계정 | 카카오·애플 로그인, 내 정보 조회, 회원 탈퇴 |
| 반려동물 | CAT 또는 DOG 선택·변경, 월 예산 사용률에 따른 상태, 기록 수에 따른 성장 |
| 지출 | 금액·날짜·고정 카테고리·메모 직접 입력, 월 목록, 수정·삭제 |
| 예산 | 월별 목표 금액 설정·변경, 해당 월 사용률과 남은 금액 조회 |
| 통계 | 월 총지출과 카테고리별 합계·비중 |

한 계정은 반려동물 한 마리만 선택한다. 지출은 양의 정수 원화이며 수입은 기록하지 않는다. 카테고리는 `FOOD`, `CAFE`, `TRANSPORT`, `SHOPPING`, `HEALTH`, `LIVING`, `OTHER`의 고정 목록이다. 월의 기준은 `Asia/Seoul` 달력이다.

## 4. 대표 경험

1. 사용자는 소셜 로그인 후 CAT 또는 DOG를 선택하고 이번 달 예산을 설정한다. 예산 설정은 나중에 할 수도 있다.
2. 사용자는 지출 날짜, 금액, 카테고리, 선택 메모를 입력한다. 저장 즉시 월 목록·통계·예산 사용률이 갱신된다.
3. 홈에는 총지출, 남은 금액 또는 초과 금액, 반려동물 상태와 성장 단계가 표시된다. 예산이 없다면 예산 사용률 대신 설정 안내를 표시한다.
4. 잘못 입력한 지출을 수정하거나 삭제하면 해당 월 통계와 반려동물 상태가 다시 계산된다.

## 5. 계산 규칙

- `monthly_spent`: 해당 사용자의 해당 월 `expenses.amount` 합계. 내역이 없으면 0.
- `usage_rate`: 예산이 있을 때 `monthly_spent / monthly_budget.amount × 100`. 표시값은 소수 첫째 자리 반올림, 상태 판정은 반올림 전 값 사용.
- 상태: 예산 없음 `NO_BUDGET`, 사용률 70% 미만 `STABLE`, 70% 이상 100% 미만 `CAUTION`, 100% 이상 `OVER_BUDGET`. 정확히 100%도 초과 구간으로 분류하되 문구는 “예산을 모두 사용했어요”로 구분한다.
- 성장: 현재 남아 있는 지출 건수 `n`으로 `level = min(5, 1 + floor(n / 10))`, `progress = n % 10`을 계산한다. 5레벨에서는 `progress = 0`. 수정은 건수를 바꾸지 않고, 삭제하면 성장 단계가 내려갈 수 있다. 금액을 많이 쓰도록 유도하지 않기 위해 금액은 성장에 사용하지 않는다.

## 6. 성공 기준

초기 검증 지표는 가입 후 24시간 내 첫 지출 입력률, 첫 7일 내 월 예산 설정률, 2주차 지출 재입력률, 사용자 테스트에서 반려동물 상태의 의미를 정확히 이해한 비율이다. 목표 수치는 첫 사용자 테스트 후 기준선을 잡는다. 서버는 이 지표를 위한 별도 이벤트 테이블을 만들지 않고 현 단계에서 가능한 집계와 인터뷰를 사용한다.

## 7. 범위 밖

계좌 연동, CODEF, 금융결제원, 자동 거래 수집·동기화, 이체 매칭, 환불 자동 연결, 수입, 자동 카테고리 분류, 거래 수정 이력, 사용자별 임계값, 푸시, 크레딧, 상점, 아이템, 관리자 기능은 MVP에서 제외한다. 상세 계약은 `02-requirements-features.md`, API는 `08-feature-implementation-map.md`, DB는 `09-db-design.md`에 따른다.

## 8. 주요 위험

수동 입력을 잊으면 실제 지출과 앱 합계가 다를 수 있으므로 화면에 “직접 기록한 지출 기준”을 명시한다. 예산 경고는 비난하는 문구를 피한다. 다른 사용자의 지출이나 예산이 보이지 않도록 모든 조회·변경을 인증 사용자 범위로 제한한다.
