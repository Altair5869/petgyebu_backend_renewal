# PRD: Petgyebu 리뉴얼 MVP

- 갱신: 2026-10-10
- 대상: `petgyebu_backend_renewal` 백엔드와 연결되는 앱
- 상태: 확정된 MVP 제품 요구사항. 계산·데이터·API의 정확한 계약은 [00-renewal-development-guide.md](00-renewal-development-guide.md)를 우선한다.
- 근거: [2026 매형즈 스터디 회의록](https://app.notion.com/p/3eaa117053d780c5b032fbe193c6a9cb?source=copy_link), [사용자 흐름](https://www.figma.com/board/viSG5enjuib5thvwwIUY0m), [8개 화면 와이어프레임](https://www.figma.com/design/Ttkey5th2ALEig6hI1IWrz), 이후 사용자와 확정한 결정

## 1. 제품 목표

사용자는 **현재 펫의 상태를 보고 예산 대비 소비를 직관적으로 파악**한다. 숫자는 그 상태를 확인하고 다음 지출을 결정하는 근거로 제공한다. 펫은 현재 월의 소비만 표현하며, 지난달을 포함한 과거 월은 숫자로 돌아본다.

이 서비스의 지출은 사용자가 가계부에 넣기로 선택해 직접 입력한 내역이다. 계좌의 모든 거래나 실제 소비 전체를 수집·보장하지 않는다. 앱에는 “직접 기록한 지출 기준”이라는 맥락을 분명히 보여준다.

초기 대상은 직접 지출을 기록하며 월 예산을 관리하려는 사용자다. 연령대나 정량 목표는 아직 확정하지 않았다. 검증할 가설은 펫 상태가 예산 사용 정도를 이해하기 쉽게 만들고, 입력 부담이 낮으면 기록을 이어가기 쉽다는 것이다.

## 2. MVP 범위

| 영역 | 제공 경험 |
|---|---|
| 계정 | 카카오·구글 로그인, 로그인 유지와 갱신, 로그아웃, 내 정보 조회, 회원 탈퇴. 한 계정의 활성 로그인은 하나만 유지 |
| 온보딩 | 로그인 후 CAT 또는 DOG 한 마리 선택, 현재 월 예산 설정을 완료한 뒤 홈 진입 |
| 현재 홈 | 펫 상태 → 예산 잔액·사용률 → 지출 기록 순서로 표시. 지출 0건이면 안정 상태와 첫 기록 안내 |
| 지출 | 금액·날짜·카테고리·선택 메모를 직접 입력하고, 현재·과거 월의 지출 조회·수정·삭제 |
| 예산 | 현재 월 예산 설정·변경. 과거 월 예산 조회. 새 달에는 직전 예산을 제안하되 확인 후 저장 |
| 상세 통계 | 현재·과거 월의 총지출·건수, 카테고리별 금액·비중, 지출 내역 조회 |

한 계정은 펫 한 마리를 선택하며 종류를 나중에 변경할 수 있다. 펫 성장·레벨·경험치는 제공하지 않는다. 지출은 양의 원화 정수이고, 수입은 기록하지 않는다. 카테고리는 `FOOD`, `CAFE`, `TRANSPORT`, `SHOPPING`, `HEALTH`, `LIVING`, `OTHER`의 일곱 가지다. 월과 ‘오늘’의 기준 시간대는 `Asia/Seoul`이다.

## 3. 핵심 사용자 흐름

1. **첫 진입:** 카카오 또는 구글로 로그인한다. 펫 종류와 현재 월 예산을 차례로 확정해야 홈으로 이동한다. 둘 다 미설정이면 펫 선택부터 안내한다.
2. **새 달 진입:** 직전 달 예산을 입력란에 제안한다. 사용자가 확인하거나 변경해 저장하기 전에는 새 달 예산이 생기지 않고 현재 홈에 들어갈 수 없다.
3. **지출 기록:** 날짜는 기본으로 오늘이 채워진다. 금액과 날짜는 필수이고 카테고리를 고르지 않으면 기타(`OTHER`)로 기록한다. 메모는 선택이며 최대 100자다. 미래 날짜는 입력할 수 없다. 저장 후 해당 월의 지출·통계와, 현재 월이면 홈의 펫 상태가 갱신된다.
4. **기록 정정:** 지출 수정 화면은 입력 화면에 기존 값을 채워 재사용한다. 메모를 지우면 목록의 제목은 카테고리 이름으로 바뀐다. 수정 후에는 수정된 날짜가 속한 월의 목록으로 이동한다. 삭제는 수정 화면에서 확인을 거쳐 진행한다. 과거 월 지출도 수정·삭제할 수 있다.
5. **월별 돌아보기:** 월 선택기에서 현재 월과 지출이 없는 달을 포함한 과거 월을 고른다. 미래 월은 선택하지 않는다. 과거 월에는 펫 이미지·표정·상태를 보여주지 않는다. 예산이 없는 과거 월에도 지출 합계·건수·카테고리 통계는 보여준다.
6. **계정 종료:** 로그아웃하면 앱과 서버의 현재 로그인이 종료된다. 탈퇴하면 계정 및 그 계정의 지출·예산을 삭제한다.

## 4. 화면 정보와 탐색

현재 홈의 첫 시선은 펫 상태에 둔다. 다음으로 예산 잔액과 사용률을 확인하고 지출 기록으로 이어지게 한다. 정확히 예산에 도달했으면 잔액 0원, 초과했다면 초과 금액을 명확히 구분한다. 예산 경고와 초과 표현은 사용자를 비난하지 않는다.

상세 통계의 순서는 **월 선택 → 지출 총액·건수 → 카테고리별 금액·비중 → 전체 지출 내역**이다. 카테고리 영역은 일반 세로 스크롤로 본다. 지출이 있는 카테고리만 금액 순으로 보여준다. 지출 목록은 무한 스크롤로 이어서 불러오며, 빈 목록·로딩·오류 재시도·마지막 페이지를 구분한다. 월을 바꾸거나 지출을 변경하면 목록을 처음부터 다시 불러온다.

목록에는 금액을 항상 표시한다. 메모가 있으면 메모가 제목, 날짜·카테고리가 보조 정보다. 메모가 없으면 카테고리가 제목, 날짜가 보조 정보다. 긴 제목은 목록에서 한 줄로 줄이고 수정 화면에서는 전체를 확인할 수 있다.

## 5. 예산 계산과 펫 상태

해당 월 사용자가 기록한 지출의 합계가 `spentAmount`다. `budgetBalanceAmount = budgetAmount - spentAmount`이며, 양수는 남은 금액, 0은 예산 도달, 음수는 예산 초과다. 사용률은 `spentAmount / budgetAmount × 100`으로 계산한다. 상태 판정에는 표시를 위해 자르기 전의 실제 비율을 사용한다. 표시용 `usagePercent`는 소수 첫째 자리에서 버리고, 정수로 떨어지면 화면에서 `.0`을 숨긴다.

| 실제 사용률 | 펫 상태 | 전달할 인상 |
|---|---|---|
| 0% 이상 50% 미만 | 안정 (`STABLE`) | 편안함 |
| 50% 이상 80% 미만 | 주의 (`CAUTION`) | 눈이 커지고 남은 예산에 집중함. “벌써 반을 썼다”는 느낌 |
| 80% 이상 100% 미만 | 경고 (`WARNING`) | 시선이 사용자와 예산 사이를 오가고 앞발이 안절부절함 |
| 100% 이상 | 예산 도달 (`BUDGET_REACHED`) | 움직임을 멈추고 빈 예산 게이지를 놀란 눈으로 봄. “벌써 다 썼어요…”라는 느낌 |

정확히 50%, 80%, 100%는 각각 다음 상태로 바뀐다. 30%에는 별도 상태가 없다. 100%를 넘겨도 상태는 `BUDGET_REACHED`로 유지하고, 음수 잔액을 초과 금액으로 표현한다. 펫을 아프거나 벌받는 모습으로 그리지 않는다.

현재 월 예산을 수정하면 지출 합계는 그대로 두고 사용률·잔액·상태를 새 예산에 맞춰 갱신한다. 지출이 없으면 안정 상태다. 예산이 없는 달(과거 월과 현재 월 통계)은 예산·사용률·잔액을 ‘미설정’으로 보여주되 지출 통계는 유지한다. 카테고리 비중은 월 총지출 대비 해당 카테고리 지출의 비율로, 소수 첫째 자리에서 반올림한다.

## 6. 수용 기준

1. 신규 사용자는 펫과 현재 월 예산을 설정한 뒤에만 현재 홈을 볼 수 있다. 새 달 예산은 직전 금액을 제안하지만 확인 전에는 저장되지 않는다.
2. 예산 100,000원에서 지출 합계가 0원·30,000원이면 안정, 50,000원이면 주의, 80,000원이면 경고, 100,000원·110,000원이면 예산 도달이다. 110,000원일 때 예산 잔액은 -10,000원이다.
3. 49.99%는 49.9%·안정으로 표시한다. 상태는 표시용 숫자가 아닌 실제 비율을 따른다.
4. 지출 생성·수정·삭제나 현재 월 예산 변경 직후 관련 월의 숫자가 일치한다. 지출 날짜가 다른 월로 바뀌면 두 월을 갱신한다.
5. 과거 월에는 펫이 나오지 않는다. 예산이 없는 과거 월과 지출이 0건인 월도 조회할 수 있다.
6. 메모가 없는 지출은 목록에 카테고리 제목이 나온다. 지출 목록은 다음 내역을 계속 불러올 수 있고 마지막에서는 추가 로딩을 멈춘다.
7. 새 로그인·로그아웃·탈퇴 후 종료된 로그인의 토큰으로 사용자 데이터에 접근할 수 없다.

## 7. 검증할 가설과 성공 신호

우선 사용자 테스트에서 **숫자 설명 없이도 펫 상태가 예산 대비 소비를 뜻한다는 점을 이해하는지** 확인한다. 이어서 지출·예산 변경 후 상태와 잔액의 변화를 이해하는지, 입력 후 기록을 계속하는지 본다. 첫 지출 입력률, 온보딩의 예산 설정 완료율, 다음 주 재기록률은 초기 관찰 지표로 사용할 수 있다. 목표 수치는 첫 사용자 테스트 후 정한다. 이 지표만을 위한 별도 이벤트 테이블은 MVP에 두지 않는다.

## 8. 제외 범위와 후속 결정

계좌 연동·자동 거래 수집, 수입, 자동 카테고리 분류, 환불 자동 연결과 변경 이력, 펫 성장·레벨·경험치, 사용자별 상태 경계, 푸시, 보상·상점·아이템, 관리자 기능은 MVP에서 제외한다. 전체 취소는 지출 삭제, 일부 환불은 금액 수정으로 처리한다.

카카오·구글 로그인은 SDK 토큰을 서버가 검증하는 방식으로 확정했고, 앱인토스 미니앱은 토스 로그인만 허용하므로 토스 로그인은 후속 작업이다. 월별 지출 합계 캐시는 정확한 DB 조회를 먼저 구현하고 성능·동시성을 측정한 뒤 실험하여 출시 적용을 결정한다. 캐시를 출시 필수 기능으로 취급하지 않는다.

수동 입력이 빠지면 실제 소비와 앱 합계가 달라질 수 있다. 숫자의 범위를 “직접 기록한 지출”로 설명하고, 모든 사용자 데이터는 로그인한 계정 안에서만 조회·변경되도록 한다. 상세 기능·API·DB 문서를 수정할 때는 [개발 기준](00-renewal-development-guide.md)의 확정된 계약과 대조한다.
