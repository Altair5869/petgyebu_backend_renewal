# 요구사항 및 기능명세서: Petgyebu 리뉴얼 MVP

- 갱신: 2026-10-10
- 기준 문서: [00-renewal-development-guide.md](00-renewal-development-guide.md), [01-prd.md](01-prd.md)
- 상태: 기능별 MVP 요구사항. 수치·응답·API·데이터 계약이 충돌하면 `00-renewal-development-guide.md`를 우선한다.
- 기능 ID: `F-M01`~`F-M06`. 이전 제품의 ID와 검토 기록은 현재 구현 기준으로 사용하지 않는다.

## 공통 계약

- 카카오·구글 로그인 외의 인증 공급자는 제공하지 않는다. 인증된 API는 Bearer 액세스 토큰을 사용한다. 한 계정의 활성 로그인은 하나다.
- 금액은 원화 정수이며 지출·예산 금액은 1원 이상 1억 원(100,000,000) 이하다. 날짜는 `YYYY-MM-DD`, 월은 연도 포함 `YYYY-MM`이고 경계는 `Asia/Seoul`이다. 미래 월을 조회·선택하거나 미래 날짜의 지출을 기록할 수 없다. 지출 날짜는 2000-01-01 이후, 조회 월은 2000-01 이후다.
- 카테고리는 `FOOD`, `CAFE`, `TRANSPORT`, `SHOPPING`, `HEALTH`, `LIVING`, `OTHER`다. 지출 생성에서 카테고리 생략 또는 `null`은 `OTHER`로 저장한다. 수정에서 명시적인 `category: null`은 오류다.
- 사용자가 직접 입력한 지출만 합산한다. 사용자의 계정 범위를 벗어난 지출·예산은 조회·변경할 수 없다. 다른 사용자의 지출 ID와 존재하지 않는 지출 ID는 구분 없이 404로 처리한다.
- 입력 형식·범위 오류는 400, 인증 실패는 401이다. 펫 또는 현재 월 예산이 없어 홈에 들어갈 수 없으면 각각 409 `PET_REQUIRED`, `BUDGET_REQUIRED`를 반환한다. 둘 다 없을 때는 펫 선택을 먼저 안내한다.
- 월 지출 합계는 DB의 지출 내역에서 계산한다. 펫 상태·월 합계·사용률은 별도로 영구 저장하지 않는다. 변경 후 관련 월을 다시 조회하면 최신 값이 일치해야 한다.

## F-M01 계정과 인증

| 항목 | 요구사항 |
|---|---|
| 로그인 | 카카오·구글로 로그인한다. 서버는 공급자가 부여한 사용자 ID를 `provider_user_id`로 저장하고 `(provider, provider_user_id)`로 사용자를 찾거나 생성한다. 이메일은 계정 식별자로 사용하지 않는다. 같은 사람의 두 공급자 계정은 자동 통합하지 않는다. 앱은 카카오 SDK 액세스 토큰 또는 구글 ID 토큰을 credential로 보낸다. 앱인토스 미니앱은 토스 로그인만 허용하므로 별도 후속 작업이다. |
| 토큰 | 로그인 성공 시 서버 자체 액세스·리프레시 토큰을 발급한다. 액세스 토큰은 15분, 리프레시 토큰은 마지막 사용 후 30일 유효하다. 리프레시할 때 둘 다 새로 발급하고 이전 리프레시 토큰을 무효화한다. 원본 리프레시 토큰은 DB에 저장하지 않는다. |
| 한 활성 로그인 | 새 로그인은 같은 계정의 이전 로그인을 무효화한다. 액세스 토큰의 세션 ID와 사용자의 `active_session_id`가 일치해야 한다. `active_session_id`는 로그인 식별자이며 기기 식별자가 아니다. `device_id`는 MVP에 저장하지 않는다. |
| 로그인 유지 | 앱을 닫았다 열어도 유효한 리프레시 토큰으로 로그인 상태를 이어간다. 30일간 사용하지 않아 만료되면 소셜 로그인을 다시 한다. |
| 내 정보 | 사용자 ID, 공급자, 선택한 펫 종류를 반환한다. 펫 선택 전에는 `petType: null`이다. 마지막 소셜 로그인 성공 시 `last_login_time`을 갱신한다. |
| 로그아웃 | 서버의 현재 활성 로그인을 무효화하고 앱에 보관한 토큰도 삭제한다. 이후 이전 액세스·리프레시 토큰은 거부된다. |
| 탈퇴 | 사용자의 명시적 확인 뒤 지출 → 월 예산 → 사용자 순으로 한 DB 트랜잭션에서 삭제한다. DB 삭제 연쇄 동작에 맡기지 않는다. 실패 시 전체 삭제를 롤백하고 탈퇴 후 남은 토큰을 거부한다. 탈퇴와 겹친 지출 생성·예산 PUT이 사용자 FK 위반으로 실패하면 `401 UNAUTHORIZED`다. 탈퇴 중 같은 사용자의 행이 끼어들어 FK 위반이 나면 삭제 트랜잭션을 처음부터 다시 실행한다(최대 3회, 모두 실패하면 `500 INTERNAL_ERROR`). |

## F-M02 펫 선택과 현재 상태

| 항목 | 요구사항 |
|---|---|
| 선택·변경 | 계정당 `CAT` 또는 `DOG` 한 종류를 선택한다. 최초 홈 진입 전 선택은 필수다. 나중에 변경해도 지출·예산은 바뀌지 않는다. 별도 펫 테이블이나 성장 데이터는 두지 않는다. |
| 표시 범위 | 펫 이미지·표정·상태는 현재 월 홈에만 표시한다. 지난달을 포함한 과거 월은 숫자만 표시한다. |
| 판정 | 현재 월 지출 합계와 예산의 실제 비율로 상태를 정한다. 표시용 사용률로 판정하지 않는다. 0건은 `STABLE`; 50% 미만 `STABLE`; 50% 이상 80% 미만 `CAUTION`; 80% 이상 100% 미만 `WARNING`; 100% 이상 `BUDGET_REACHED`다. 정확히 50%·80%·100%는 새 구간에 속한다. |
| 100% 초과 | 별도 상태를 만들지 않는다. `BUDGET_REACHED`를 유지하고 음수 예산 잔액의 절댓값을 초과 금액으로 표시한다. |
| 연출 | 안정은 편안함, 주의는 커진 눈으로 남은 예산에 집중, 경고는 시선과 앞발의 안절부절, 예산 도달은 멈춘 움직임과 빈 게이지를 바라보는 놀란 눈으로 표현한다. 비난·질병·처벌 이미지는 사용하지 않는다. |

## F-M03 수동 지출

| 항목 | 요구사항 |
|---|---|
| 생성 | 금액과 지출 날짜는 필수다. 앱은 날짜 입력란을 오늘로 채우지만 API 요청에는 날짜를 반드시 보낸다. 서울 시간 기준 오늘 또는 과거 날짜만 허용한다. 카테고리 생략·`null`은 `OTHER`다. 메모는 선택이며 앱·서버에서 최대 100자(유니코드 코드 포인트)이고 NUL 문자는 400이다. 생성 시 메모 생략·빈칸·공백만 입력은 `null`로 저장한다. |
| 목록 | 현재 또는 과거 월의 지출을 날짜 내림차순, 같은 날짜는 ID 내림차순으로 조회한다. 커서 기반 무한 스크롤이며 기본 20건, 최대 50건이다. 응답은 `items`와 `nextCursor`, 마지막은 `nextCursor: null`이다. 지출이 없으면 빈 배열과 `nextCursor: null`이다. `limit`이 1~50 밖이면 보정하지 않고 400 `INVALID_REQUEST`, 미래 월·2000-01 이전 월도 400 `INVALID_REQUEST`다. |
| 커서 | 앱은 커서를 해석하지 않고 받은 그대로 다음 요청에 보낸다. 다른 사용자·월의 커서나 잘못된 형식은 400 `INVALID_CURSOR`다. 월 변경 또는 지출 생성·수정·삭제 뒤 기존 커서를 버리고 첫 페이지부터 다시 조회한다. |
| 단건 조회 | 지출 수정 화면의 초기값을 위해 본인 지출의 금액·날짜·카테고리·메모를 조회한다. 없거나 다른 사용자의 지출은 404 `EXPENSE_NOT_FOUND`다. |
| 수정 | 전달한 필드만 바꾸고 생략한 필드는 유지한다. `memo: null`과 빈칸·공백만 있는 메모는 메모 삭제다. `amount`, `expenseDate`, `category`에 명시적으로 `null`을 보내면 400이다. 날짜를 다른 월로 변경할 수 있으며 수정 후 새 날짜가 속한 월의 목록으로 이동한다. |
| 삭제 | 수정 화면에서만 삭제 동작을 제공하고 실행 전 확인한다. 삭제 후 관련 월 합계·통계·현재 펫 상태를 갱신한다. |
| 중복·환불 | 동일 날짜·금액·카테고리의 여러 지출을 허용한다. 전체 취소는 삭제, 일부 환불은 금액 수정으로 처리한다. 별도 환불 거래나 수정 이력은 두지 않는다. |

목록에서 금액은 항상 표시한다. 메모가 있으면 메모가 제목이고 날짜·카테고리가 보조 정보다. 메모가 없으면 카테고리 이름이 제목이고 날짜가 보조 정보다. 긴 메모는 목록에서 한 줄로 줄이고 수정 화면에서 전체를 확인한다. 생성·수정·삭제 후 영향받은 월의 목록과 통계를 다시 조회하며, 현재 월이 영향받으면 홈도 갱신한다. 날짜가 월을 넘으면 이전 월과 새 월을 모두 갱신한다.

## F-M04 월 예산

| 항목 | 요구사항 |
|---|---|
| 최초 설정 | 현재 월 예산은 홈 진입 전 필수다. 사용자와 월마다 하나의 양의 원화 정수 금액을 저장한다. |
| 새 달 | 직전 달 예산을 입력란에 제안한다. 사용자가 확인하거나 수정해 저장하기 전에는 새 달 예산을 자동 생성하지 않는다. 월 전환 배치는 없다. |
| 설정·변경 | 현재 월에만 PUT으로 설정·변경한다. 같은 월에 다시 PUT하면 금액을 교체한다. 동시 정상 PUT은 단일 upsert로 처리해 클라이언트 재시도 없이 성공하고 한 행만 남긴다. 과거 예산은 변경하지 않으며 미래 월 예산도 미리 저장하지 않는다. 현재 월이 아닌 PUT은 400 `INVALID_REQUEST`(`month`)다. |
| 조회 | 현재·과거 월을 조회한다. 미설정 월은 `amount: null`이다. 2000-01 이전·미래·형식 오류 월은 지출 목록과 같이 400 `INVALID_REQUEST`(`month`)다. 과거 월에 예산이 없어도 지출 합계·건수·카테고리 통계는 조회할 수 있다. |
| 저장 경계 | API의 `YYYY-MM`을 해당 월 1일의 `DATE`로 저장한다. `(user_id, budget_month)`는 유일하다. |

예산 변경 후 지출 합계는 그대로 두고 사용률·예산 잔액·현재 월 펫 상태를 다시 계산한다. 예산 PUT은 신규·변경 모두 200으로 응답한다.

## F-M05 월별 상세 통계

| 항목 | 요구사항 |
|---|---|
| 월 탐색 | 현재 월과 모든 과거 월을 선택할 수 있다. 지출이 없는 달도 0원·0건으로 보여준다. 미래 월은 선택하지 않는다. 과거 월에는 펫 데이터가 없다. |
| 정보 순서 | 월 선택 → 지출 총액·건수 → 카테고리별 금액·비중 → 전체 지출 내역. 카테고리는 일반 세로 스크롤, 전체 내역은 커서 기반 무한 스크롤이다. |
| 합계·건수 | 해당 사용자·월의 지출 금액 합계와 건수를 현재 DB 내역으로 계산한다. 지출이 없으면 `spentAmount: 0`, `expenseCount: 0`, 빈 카테고리 배열이다. |
| 카테고리 | 지출이 있는 항목만 금액 내림차순으로 반환한다. 동률은 고정 코드 순서 `FOOD, CAFE, TRANSPORT, SHOPPING, HEALTH, LIVING, OTHER`다. 항목마다 금액·건수·월 합계 대비 비중을 제공한다. 비중은 소수 첫째 자리 반올림이며 표시 비중 합계가 100%와 조금 달라도 금액을 보정하지 않는다. |
| 예산 관련 값 | 예산이 있으면 예산 금액·사용률·부호가 있는 예산 잔액을 반환한다. 그 달 예산이 없다면(과거·현재 월 모두, 409 아님) 이 세 값만 `null`이며 지출 통계는 유지한다. |

## F-M06 현재 월 홈

| 항목 | 요구사항 |
|---|---|
| 진입 조건 | 펫과 현재 월 예산을 모두 설정해야 한다. 미설정이면 409로 해당 설정을 안내하며 둘 다 없으면 펫이 먼저다. |
| 대상 | `GET /api/v1/home`은 현재 서울 시간 기준 월 전용이다. 월 선택 파라미터를 받지 않는다. |
| 응답 | `month`, `petType`, `petState`, `budgetAmount`, `spentAmount`, `usagePercent`, `budgetBalanceAmount`를 제공한다. 지출 목록·카테고리 통계·성장 데이터는 포함하지 않는다. |
| 화면 | 펫 상태 → 예산 잔액·사용률 → 지출 기록 순서다. 0건이면 안정 상태와 첫 기록 안내를 보여준다. 현재 월 예산·지출 변경 뒤 다시 조회하면 최신 상태가 표시된다. |

### 계산 규칙

- 월 범위는 `Asia/Seoul`의 `[월 첫날, 다음 달 첫날)`이다. `spentAmount`는 그 범위의 사용자 지출 합계다.
- `budgetBalanceAmount = budgetAmount - spentAmount`. 양수는 남은 금액, 0은 예산 도달, 음수는 초과 금액이다.
- 실제 사용률은 `spentAmount / budgetAmount × 100`이다. 펫 상태는 실제 비율로 판정한다. API의 `usagePercent`는 소수 첫째 자리에서 **버림**하고 앱은 소수부가 0이면 `.0`을 숨긴다. 예를 들어 실제 49.99%는 표시 49.9%·안정이다.
- 월 예산이 없는 과거 월에서는 `budgetAmount`, `usagePercent`, `budgetBalanceAmount`가 `null`이다.
- 정확한 응답 필드·상태 코드·오류 계약은 [개발 기준 8절](00-renewal-development-guide.md)을 따른다.

## 인수 기준

1. 최초 로그인 후 펫과 현재 월 예산을 확정해야 홈에 들어간다. 새 달에는 직전 예산이 제안되지만 확인 전에는 저장되지 않는다.
2. 예산 100,000원에서 합계 0원·30,000원은 안정, 50,000원은 주의, 80,000원은 경고, 100,000원·110,000원은 예산 도달이다. 110,000원의 잔액은 -10,000원이다.
3. 지출 생성·수정·삭제와 예산 변경 뒤 홈·상세 통계의 해당 월 금액이 일치한다. 지출 날짜가 다른 월로 바뀌면 두 월이 갱신된다.
4. 과거 월은 숫자만 보여주며, 예산이 없거나 지출이 없는 과거 월도 통계를 조회할 수 있다. 현재 월 예산만 변경할 수 있다.
5. 메모 삭제 후 목록 제목은 카테고리다. 카테고리 없이 생성하면 `OTHER`이고 수정에서 `category: null`은 오류다. 미래 날짜는 오류다.
6. 무한 스크롤은 날짜·ID 내림차순으로 끝까지 이어지고 다른 월·잘못된 커서는 거부된다. 다른 사용자의 지출 조회·변경은 404다.
7. 같은 계정으로 새 로그인하거나 로그아웃·탈퇴하면 이전 액세스·리프레시 토큰이 거부된다. 탈퇴 중 실패하면 계정·지출·예산 삭제가 함께 롤백된다.

## MVP 제외 및 후속 결정

펫 성장·레벨·경험치, 수입, 자동 금융 연동·거래 수집, 자동 분류, 푸시, 보상·상점·아이템, 사용자별 상태 경계, 변경 이력, 별도 집계 테이블은 MVP에서 제외한다. 앱인토스용 토스 로그인과 월 합계 캐시의 출시 적용·제품은 후속 결정이다. 캐시는 DB 조회를 먼저 정확하게 구현하고 측정한 뒤 월 합계만 실험하며, 출시 필수 조건으로 두지 않는다.
