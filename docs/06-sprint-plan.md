# 스프린트 플랜: Petgyebu MVP

- 기준일: 2026-09-25
- 기능·API: `02-requirements-features.md`, `08-feature-implementation-map.md`
- 기간은 팀 속도에 맞춰 정한다. 각 스프린트 완료 조건을 충족한 뒤 다음으로 넘어간다.

## Sprint 0 — 새 프로젝트와 계정

- React Native 앱과 Spring Boot 백엔드의 새 저장소를 만들고, 백엔드는 Gradle Groovy·Spring Web MVC·Spring Data JDBC·PostgreSQL·Flyway로 시작한다.
- 새 빈 DB에 `09-db-design.md`의 3테이블 마이그레이션을 적용한다. 이전 프로젝트의 마이그레이션은 가져오지 않는다.
- `users`와 소셜 로그인·내 정보·탈퇴를 구현한다 (`F-M01`).
- 인증된 요청의 사용자 존재 검증을 확인한다.
- **완료 조건:** 카카오·애플 중 준비된 공급자로 로그인하여 본인 정보 조회 가능, 탈퇴 후 토큰 거부. 두 공급자 설정은 각 제공자 연동 완료 시 함께 검증한다.

## Sprint 1 — 수동 지출과 반려동물 선택

- `expenses` 테이블, 고정 카테고리, 생성·월 목록·부분 수정·삭제를 구현한다 (`F-M03`).
- `users.pet_type` 선택·변경 및 지출 건수 기반 성장 계산을 구현한다 (`F-M02`).
- **완료 조건:** 다른 사용자의 지출 접근 거부, 날짜 이동·삭제 후 두 월 목록 일치, 성장 계산 경계 확인.

## Sprint 2 — 월 예산과 홈 상태

- `monthly_budgets`와 월별 예산 설정·조회를 구현한다 (`F-M04`).
- 공통 월 지출 합계로 예산 사용률과 홈 상태를 계산한다 (`F-M06`).
- **완료 조건:** 미설정·0건·정확히 70%·100%·100% 초과에서 문서와 같은 값 반환.

## Sprint 3 — 월별 통계와 출시 점검

- 월 총액·건수·카테고리별 합계·비중을 구현한다 (`F-M05`).
- 지출 생성·수정·삭제와 예산 변경 후 목록·통계·홈 값이 일치하는지 통합 검증한다.
- React Native 앱에는 직접 기록 기준 문구, 빈 상태, 탈퇴 확인을 연결한다.
- **완료 조건:** `08`의 API 12개, `09`의 테이블 3개가 동일한 규칙을 따른다. 새 MVP에 없는 외부 금융·보상 경로는 배포 대상에서 제거한다.

## 순서의 이유

계정이 지출 소유권의 기반이다. 지출이 먼저 있어야 예산 사용률과 통계를 검증할 수 있다. 월 집계 함수는 홈과 통계가 공유해 숫자가 어긋나지 않게 한다.
