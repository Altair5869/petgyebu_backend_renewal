# DB 설계: Petgyebu MVP

- 기준일: 2026-09-25
- PostgreSQL 16 기준. 논리 테이블은 **`users`, `expenses`, `monthly_budgets` 3개**다.
- 기존 `sources/09-db-design.md`의 17테이블 설계는 이전 자동 연동 제품의 이력이다.

## 관계와 소유권

```text
users (1) ──< expenses (N)
     └──────< monthly_budgets (N, 월마다 최대 1건)
```

지출과 예산은 사용자에 직접 소속된다. 계정 삭제 시 두 자식 테이블을 함께 삭제해야 하므로 이 두 FK에만 `ON DELETE CASCADE`를 사용한다. 그 외 FK와 삭제 연쇄는 없다.
Spring Data JDBC에서는 `expenses.user_id`와 `monthly_budgets.user_id`를 ID 값으로 다루고, 사용자 객체 안에 지출·예산 컬렉션을 매핑하지 않는다. 월 집계는 명시적 SQL로 조회한다.

## 테이블

### `users`

| 컬럼 | 타입 | 제약·뜻 |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | PK |
| `provider` | `VARCHAR(10)` | NOT NULL, `KAKAO` 또는 `APPLE` |
| `provider_user_id` | `VARCHAR(255)` | NOT NULL, 공급자의 안정적 사용자 ID |
| `pet_type` | `VARCHAR(10)` | NULL 허용, `CAT` 또는 `DOG` |
| `created_at` | `TIMESTAMPTZ` | NOT NULL, 가입 시각 |

`UNIQUE(provider, provider_user_id)`는 같은 공급자 계정 중복 생성을 막는다. 이메일 UNIQUE는 사용하지 않는다. 반려동물 레벨·경험치는 지출 건수에서 계산하므로 저장하지 않는다.

### `expenses`

| 컬럼 | 타입 | 제약·뜻 |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | PK |
| `user_id` | `BIGINT` | NOT NULL, `users.id` FK |
| `amount` | `BIGINT` | NOT NULL, 1원 이상 |
| `expense_date` | `DATE` | NOT NULL, 사용자가 기록한 지출 날짜 |
| `category` | `VARCHAR(20)` | NOT NULL, 고정 7개 카테고리 |
| `memo` | `VARCHAR(200)` | NULL 허용 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL |

같은 사용자·날짜·금액·카테고리의 지출 여러 건을 허용한다. 은행 거래 ID, 환불 ID, 자동 분류 출처, 변경 이력은 없다. `(user_id, expense_date, id)` 인덱스는 월 목록과 사용자별 날짜 범위 조회를 돕는다.

### `monthly_budgets`

| 컬럼 | 타입 | 제약·뜻 |
|---|---|---|
| `id` | `BIGINT GENERATED BY DEFAULT AS IDENTITY` | PK |
| `user_id` | `BIGINT` | NOT NULL, `users.id` FK |
| `budget_month` | `DATE` | NOT NULL, 해당 월 1일만 허용 |
| `amount` | `BIGINT` | NOT NULL, 1원 이상 |
| `created_at` | `TIMESTAMPTZ` | NOT NULL |
| `updated_at` | `TIMESTAMPTZ` | NOT NULL |

`UNIQUE(user_id, budget_month)`는 월별 예산 하나라는 제품 규칙을 보장한다. 이 유니크 인덱스의 선행 열 `user_id`는 부모 삭제 시 자식 검색에도 사용된다.

## 새 기준선 DDL 예시

```sql
CREATE TABLE users (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  provider VARCHAR(10) NOT NULL CHECK (provider IN ('KAKAO', 'APPLE')),
  provider_user_id VARCHAR(255) NOT NULL,
  pet_type VARCHAR(10) CHECK (pet_type IN ('CAT', 'DOG')),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT uq_users_provider_identity UNIQUE (provider, provider_user_id)
);

CREATE TABLE expenses (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  amount BIGINT NOT NULL CHECK (amount > 0),
  expense_date DATE NOT NULL,
  category VARCHAR(20) NOT NULL CHECK (category IN
    ('FOOD','CAFE','TRANSPORT','SHOPPING','HEALTH','LIVING','OTHER')),
  memo VARCHAR(200),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX ix_expenses_user_date_id ON expenses (user_id, expense_date, id);

CREATE TABLE monthly_budgets (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
  budget_month DATE NOT NULL CHECK (budget_month = date_trunc('month', budget_month)::date),
  amount BIGINT NOT NULL CHECK (amount > 0),
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  CONSTRAINT uq_monthly_budgets_user_month UNIQUE (user_id, budget_month)
);
```

`updated_at`은 애플리케이션이 수정 시 직접 갱신한다. SQL 기본값은 INSERT에만 적용된다. 지출 날짜의 미래 1년 제한은 현재 시각에 따라 변하므로 서비스 검증으로 처리한다.

## 계산 쿼리와 경계

월 조회는 `expense_date >= :firstDay AND expense_date < :nextMonthFirstDay`와 인증 사용자의 `user_id`를 함께 사용한다. 합계는 `COALESCE(SUM(amount), 0)`, 건수는 `COUNT(*)`다. 카테고리 통계는 같은 조건으로 `GROUP BY category`를 사용한다. 성장용 건수는 해당 사용자의 전체 `expenses` 건수다. 앱 표시 금액은 원 단위 정수이고 합계 오버플로를 막기 위해 서비스·응답 타입도 64비트 이상으로 맞춘다.

## 제약의 이유와 이관 주의

MVP의 UNIQUE는 공급자 계정과 사용자·월 예산 두 개뿐이다. CASCADE는 탈퇴 후 사용자 소유 데이터 삭제를 보장하는 두 FK에만 있다. 잔액 경쟁이 없어 `SELECT FOR UPDATE`를 사용하지 않는다. 새 프로젝트는 빈 DB에 이 3테이블을 생성한다. 이전 프로젝트의 운영 데이터를 옮기기로 별도 결정하기 전에는 기존 DB를 변경하지 않는다.
