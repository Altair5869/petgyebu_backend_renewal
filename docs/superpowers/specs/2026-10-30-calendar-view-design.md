# 달력 보기 (F-M09) 설계

- 날짜: 2026-10-30
- 작업 ID: 백엔드 `M-014`, 앱 `APP-009`, 기능 `F-M09`
- 상태: 승인됨 (2026-10-30)

## 1. 의도

사용자는 **날짜별로 얼마 썼는지 한눈에** 보고 싶다. 지금은 월 합계·카테고리 비율·지출 목록만 있어서 "며칠에 많이 썼지?"를 보려면 목록을 내려가며 세야 한다. 달력에서 날짜를 누르면 **그날 쓴 지출 목록이 아래에** 보인다.

## 2. 목표·비목표·실패 기준

**목표**

- 월별 통계 화면 안에서 "달력 / 목록" 탭으로 달력을 연다(사용자 선택: 탭 방식 B안).
- 달력 칸마다 그날 지출 합계를 짧게 보여 준다.
- 날짜를 누르면 그날 지출 목록과 합계를 아래에 보여 준다.

**비목표**

- 주간 달력, 연간 달력, 날짜 범위 선택.
- 날짜 칸의 색 농도(히트맵), 예산 대비 일일 한도, 무지출 데이·연속 기록.
- 달력에서 바로 지출 추가(기존 "지출 기록하기"를 쓴다).
- 새 테이블, 일별 합계 저장·캐시.

**실패로 보는 경우**

- 달력 칸 합계와 그날 목록 합계, 또는 달력 전체 합과 같은 달 통계 `spentAmount`가 다르다.
- 다른 사용자의 지출이 섞인다.
- 지출을 수정·삭제하고 돌아왔는데 달력이 예전 값을 보여 준다.
- 기존 "목록" 탭의 동작(통계·목표·무한 스크롤)이 바뀐다.

## 3. 제약

- `AGENTS.md`, `docs/00-renewal-development-guide.md` 규칙을 따른다. 행은 명시적 쿼리로 읽고 합계는 Service의 도메인 객체에서 계산한다. 새 의존성·테이블·캐시는 없다.
- 월 경계·현재 월은 `Asia/Seoul` 기준이다. `{month}`는 기존과 같이 2000-01부터 서울 기준 현재 월까지만 받는다(`Months.parsePastOrCurrent`).
- 지출 날짜는 이미 서울 기준 오늘까지만 저장되므로 현재 월의 남은 날은 항상 비어 있다.

## 4. 사용자가 정한 것

- 위치: 월별 통계 화면 안의 "달력 / 목록" 탭(B안). 월 이동(‹ 2026년 10월 ›)은 탭 위에 두고 두 탭이 공유한다.
- 날짜 칸에 그날 합계를 짧게 표시하고, 날짜를 누르면 아래에 그날 지출 목록이 나온다.
- 아래 "화면 동작"의 기본값(첫 탭, 첫 선택 날짜, 금액 표시, 빈 날 문구)은 제가 제안했고, 사용자가 채팅에서 "그대로 진행"으로 받아들였다. "(제 판단)"이라고 표시한 나머지는 이 문서를 쓰면서 제가 정했다.

## 5. 백엔드 (`M-014`)

### 5.1 새 API: 날짜별 합계

`GET /api/v1/months/{month}/daily-totals`

```json
{
  "month": "2026-10",
  "days": [
    { "date": "2026-10-01", "spentAmount": 12000, "expenseCount": 2 },
    { "date": "2026-10-28", "spentAmount": 23000, "expenseCount": 2 }
  ]
}
```

- `days`는 **지출이 있는 날만** `date` 오름차순이다. 지출이 없는 달은 `days: []`다.
- `month` 오류는 기존과 같은 400 `INVALID_REQUEST`(`month`), 미인증은 401이다. 다른 오류는 없다.
- `days`의 `spentAmount` 합 = 같은 달 `GET /months/{month}/stats`의 `spentAmount`, `expenseCount` 합 = `expenseCount`다.
- 구현: 기존 `ExpenseRepository.findDayAmounts(userId, from, to)`로 행을 한 번 읽고, `MonthlySpending`과 같은 방식의 도메인 객체(예: `expense/DailySpending`)가 날짜별 합계·건수를 계산한다. 새 SQL은 없다.

### 5.2 기존 API 확장: 지출 목록 날짜 필터

`GET /api/v1/months/{month}/expenses?date=YYYY-MM-DD`

- 선택 파라미터 `date`가 있으면 그날 지출만 돌려준다. 정렬(`expenseDate DESC, id DESC`)·`limit`·`nextCursor`·응답 형식은 그대로다.
- `date`는 `YYYY-MM-DD` 형식이며 `{month}` 안의 날짜여야 한다. 형식 오류·없는 날짜·다른 달 날짜는 400 `INVALID_REQUEST`(`date`)다. 현재 월의 미래 날짜는 형식이 맞으면 허용하고 빈 목록을 돌려준다.
- 검증 순서는 `month` → `limit` → `category` → `date` → `cursor`다.
- `category`와 함께 쓸 수 있다(그날 그 카테고리).
- 구현: `date`가 있으면 조회 범위 `[from, to)`를 `[date, date + 1일)`로 좁혀 기존 네 쿼리를 그대로 쓴다. 새 SQL은 없다.
- 커서 규칙은 바꾸지 않는다. 커서는 지금처럼 발급한 사용자·월에만 묶인다. 같은 달 안에서 날짜 필터를 바꿔 커서를 재사용하면 400이 아니라 그 위치 이후의 그날 행(대개 빈 목록)을 돌려준다. 다른 사용자 데이터는 섞이지 않는다. 앱은 날짜를 바꾸면 첫 페이지부터 다시 조회한다.

### 5.3 테스트

- 날짜별 합계 도메인 객체 단위 테스트: 빈 입력, 같은 날 여러 건 합산, 오름차순 정렬.
- 날짜별 합계 API 테스트: 응답 필드, 지출 없는 달 `days: []`, 서울 월 경계(그 달 1일·말일 포함, 앞뒤 달 제외), `days` 합 = 통계 `spentAmount`·`expenseCount`, 사용자별 격리, 미래 월·형식 오류 400(`month`), 미인증 401.
- 날짜 필터 API 테스트: 그날 행만 정렬 순서대로, 커서 페이징, `category`와 함께, 다른 사용자 제외, 형식 오류·다른 달 날짜·`2026-02-30` 같은 없는 날짜 400(`date`), 검증 순서(`category` 오류가 `date`보다 먼저, `date` 오류가 `cursor`보다 먼저).
- `./gradlew test --no-daemon` 통과.

### 5.4 문서

계약이 바뀌므로 함께 갱신한다: `00`(API 표에 20번째 동작 추가 → **20개 동작·15개 고유 경로**, 응답 필드, 지출 목록 검증 순서, 상세 통계 화면 설명), `02`(`F-M09`), `03`(통계 화면 흐름), `06`(완료 조건 주석), `08`(기능·API 표·합계), `10`(`M-014`, `APP-009` 항목). 지출 목록의 `date`는 기존 경로의 파라미터라 고유 경로 수에 더하지 않는다.

## 6. 앱 (`APP-009`, 별도 앱 저장소 PR)

### 화면 동작

- 월별 통계 화면에서 월 이동 바로 아래에 "달력 / 목록" 탭을 둔다. **처음 열 때와 화면을 다시 열 때는 "목록"이 기본**이다. "목록" 탭은 지금 화면(요약·예산 줄·카테고리 비율·목표·전체 목록)과 같다.
- "달력" 탭: 일요일 시작 월 달력. 지출이 있는 날에만 칸 아래에 줄인 금액을 쓰고, 없는 날은 날짜만 보인다. 오늘은 표시한다.
- **첫 선택 날짜:** 현재 월이면 오늘, 과거 월이면 1일. 월을 바꾸면 그 규칙으로 다시 고른다.
- 날짜를 누르면 아래 카드에 "10월 28일 · 23,000원"과 그날 지출 목록(기존 지출 행 모양)을 보여 준다. 지출이 없으면 "이날은 지출이 없어요". 그날 목록은 `?date=`로 받는다.
- 달력은 **항상 전체 카테고리** 기준이다. 통계 화면에는 카테고리 필터가 없고(카테고리별 목록은 별도 `expenses/by-category` 화면), 앱은 달력에서 `category`를 보내지 않는다. 그래서 칸 합계와 그날 목록 합계가 항상 같다. 백엔드의 `date`+`category` 조합은 계약상 허용만 한다. (제 판단)
- 스크롤 구조 (제 판단): "달력" 탭은 "목록" 탭처럼 하나의 세로 목록이다. 달력과 날짜 제목을 목록 머리로 두고, 그날 지출 행을 목록 항목으로 둔다. 끝에 닿으면 다음 페이지를 이어 받는다. 스크롤 목록을 다른 스크롤 안에 넣지 않는다.
- 지출 행을 누르면 기존 수정 화면으로 가고, 돌아오면 날짜별 합계와 선택한 날 목록을 다시 읽는다. 선택한 날짜는 유지한다(수정으로 그날 지출이 없어지면 빈 문구).
- 과거 월에도 펫은 없다(기존 규칙).

### 날짜 칸 금액 표시 (제 판단)

| 그날 합계 | 표시 | 예 |
|---|---|---|
| 1,000원 미만 | 숫자 그대로 | `500` |
| 1,000원 ~ 9,999원 | 천 단위 버림 + "천" | 8,700 → `8천` |
| 10,000원 ~ 99,999,999원 | 만 단위, 소수 첫째 자리 버림 + "만" (`.0`은 생략) | 12,800 → `1.2만`, 30,000 → `3만`, 1,250,000 → `125만` |
| 100,000,000원 이상 | 억 단위, 소수 첫째 자리 버림 + "억" | `1.2억` |

버림은 홈·통계의 사용률 버림과 방향을 맞춘 것이다. 정확한 금액은 아래 카드에 원 단위로 보인다.

### 앱 검증

- Jest: 금액 표시 경계값(999, 1,000, 9,999, 10,000, 12,800, 99,999,999, 100,000,000), 달력 칸 배치(1일 요일, 말일), 첫 선택 날짜 규칙.
- Maestro(iOS): 통계 → 달력 탭 → 지출 있는 날 선택 → 목록 확인 → 지출 수정 → 돌아와 합계 갱신 확인. Android는 가능하면 확인하고, 못 하면 기록에 남긴다.

## 7. 빌더에게 맡기는 것

- 날짜별 합계 도메인 객체·Service 메서드의 이름과 위치(통계 패키지에 붙일지 등). 단, 합계는 DB 집계가 아니라 도메인 객체에서 계산한다.
- `date` 파싱 위치(`ExpenseService` 안 또는 `common` 헬퍼).
- 앱 컴포넌트 구조, 달력을 직접 그릴지(새 라이브러리 추가 없이 직접 그리는 쪽을 권장), 탭 모양.
